# 파싱 전 검사 탭

파싱 전 단계의 페이지 JSON/이미지를 기준으로 검수 규칙을 실행하고, 결과를 표/미리보기/통계로 확인하는 탭입니다.

이 탭은 두 단계로 나뉩니다.

1. 조회 시점 JSON을 스냅샷으로 확보해 실행 기준을 고정
2. 선택한 플러그인을 페이지별로 실행해 라벨 단위 오류를 화면에 반영

플러그인 자체의 작성 방법과 개별 규칙 설명은 별도 문서에서 관리합니다.

- [plugin_system/README.md](./plugin_system/README.md)
- [plugins/README.md](./plugins/README.md)

## 폴더 구조

- `page.py`: 3분할 레이아웃 조립, 상태 초기화, 상위 이벤트 연결
- `features/snapshot_flow.py`: 조회 버튼, 스냅샷 준비, 조회 중지 처리
- `features/run_flow.py`: 플러그인 실행, 실시간 결과 반영, 완료/중지 처리
- `features/row_builders.py`: 페이지/라벨 결과 행 조립
- `features/preview.py`: 오른쪽 미리보기 영역 갱신
- `features/problem_sync_strict.py`: `확인 필요` 체크/초기화와 S3 반영
- `features/page_support.py`: S3 재조회, 로그, 통계 갱신
- `features/json_snapshot_worker.py`: 조회용 JSON 스냅샷 로딩 worker
- `features/check_run_worker.py`: 페이지별 플러그인 실행 worker
- `plugin_system/`: 플러그인 계약, 로더, 레지스트리, 러너
- `plugins/`: 실제 검사 규칙 파일
- `panels/`: 좌/중/우 패널 UI
- `widgets/`: 이미지 뷰어, 툴팁, 정보 버튼 같은 보조 위젯

## 실행 흐름

1. S3에서 도서/페이지 목록을 다시 읽어옵니다.
2. 사용자가 도서를 선택하고 `조회`를 누르면 페이지별 placeholder 행을 먼저 그립니다.
3. 같은 시점의 JSON을 `.cache/preview_json` 아래에 스냅샷으로 저장합니다.
4. 스냅샷 준비가 끝나면 shape 단위 라벨 행을 만들어 중앙 패널과 미리보기에서 바로 볼 수 있게 합니다.
5. `실행`을 누르면 선택한 플러그인을 페이지별로 병렬 실행합니다.
6. 각 페이지 결과를 묶어 라벨 단위 행, 페이지 단위 통계, 오류 목록을 다시 조립합니다.
7. 필요하면 현재 필터 결과 기준으로 `확인 필요`를 저장하거나 초기화합니다.

## 병렬화 적용 지점 및 방식

### 1. 조회 시 JSON 스냅샷 준비

- 적용 파일: `features/json_snapshot_worker.py`
- 방식: `ProcessPoolExecutor`
- 단위: 페이지 JSON 1개
- 목적:
  - 조회 시점 JSON을 로컬 캐시에 고정
  - 이후 실행/미리보기/확인 필요 저장 시 기준 데이터로 재사용
- 캐시 키:
  - `s3_key|etag` 조합을 해시한 파일명

이 단계는 CPU보다는 파일 파싱과 S3 다운로드가 섞여 있지만, 페이지 수가 많을 때 병렬 조회 시간이 줄어드는 쪽에 맞춰 구현되어 있습니다.

### 2. 플러그인 검사 실행

- 적용 파일: `features/check_run_worker.py`
- 방식: `ProcessPoolExecutor`
- 단위: 페이지 1개
- 특징:
  - 각 프로세스 시작 시 플러그인 디렉터리를 한 번 로드하고 `CheckRunner`를 초기화합니다.
  - 각 작업은 `PageContext`를 만들어 선택한 플러그인 목록을 그 페이지에 대해 실행합니다.
  - 완료된 페이지 bundle은 순차적으로 메인 UI에 다시 전달되어, 도서 단위로 먼저 끝난 결과부터 화면에 점진 반영됩니다.

### 3. 확인 필요 저장/초기화

- 적용 파일: `features/problem_sync_strict.py`
- 방식:
  - 최신 JSON 사전 조회: `ThreadPoolExecutor`
  - 실제 저장: `ThreadPoolExecutor`
- 단위: 페이지 1개
- 이유:
  - 이 흐름은 S3 최신본 확인과 저장이 중심이라 I/O 병렬화가 더 적합합니다.

## 결과 행 구성 방식

### 조회 직후

조회 직후에는 아직 플러그인 실행 전이므로, 페이지별 placeholder 기반으로 화면을 채웁니다.

- 중앙 패널:
  - `set_error_only_mode(False)` 상태
  - 스냅샷으로 읽은 shape를 기준으로 라벨 행을 만듭니다.
- 라벨 행의 기본 필드:
  - `row_key`
  - `page_no`
  - `book_id`
  - `page`
  - `shape_index`
  - `label_id`
  - `label`
  - `value`
  - `is_problem`
  - `problem_reason`
  - `base_state`

즉, 조회만 끝난 시점에는 “오류가 아직 붙지 않은 shape 목록”을 먼저 보는 구조입니다.

### 실행 완료 후

플러그인 실행이 끝나면 `_materialize_check_run_outputs()`가 결과를 다시 조립합니다.

- 페이지 단위 행(`page_rows`)
  - `status`: `PASS` / `FAIL`
  - `issue_count`
  - `failed_checks`
  - `error_detail`
- 라벨 단위 행(`label_rows`)
  - shape별 스냅샷 정보 + 플러그인 오류를 합쳐 만듭니다.
  - 주요 필드:
    - `label`
    - `value`
    - `error_detail`
    - `error_type`
    - `base_state`
    - `is_problem`
    - `problem_reason`
- shape에 직접 매핑되지 않는 오류
  - 예: 플러그인 실행 오류, shape 인덱스가 없는 예외
  - `shape_index = -1`인 보조 행으로 추가됩니다.

중앙 패널은 실행 후 `set_error_only_mode(True)`로 전환되므로, 기본적으로 오류가 있는 행만 보이게 됩니다.

## 필터 및 상단 검색바 작동 방식

중앙 패널 상단에는 `도서`, `라벨`, `오류 유형`, `확인 필요 체크`, `확인 필요 초기화`, `검색`이 있습니다.

### 검색바

- 대상: 현재 결과표의 표시 텍스트 전체
- 방식:
  - 각 행의 `도서명`, `페이지`, `라벨ID`, `라벨`, `값`, `오류 세부 내용`을 이어 붙인 뒤
  - 소문자 기준 부분 문자열 검색
- 특징:
  - 정규식 검색이 아니라 단순 포함 검색입니다.
  - 현재 `오류만 보기` / 필드 필터가 먼저 적용된 상태에서 추가로 검색이 걸립니다.

### 필드 필터

- `도서`
  - 현재 조건을 만족하는 행에서 도서명을 수집해 목록을 만듭니다.
- `라벨`
  - 현재 조건을 만족하는 행에서 라벨명을 수집합니다.
- `오류 유형`
  - 각 행의 `error_type`을 기준으로 목록을 만듭니다.

필터 메뉴 값은 고정 목록이 아니라, 현재 다른 필터 조건을 통과한 행들에서 다시 계산됩니다.  
즉 하나의 필터를 고르면 다른 필터 메뉴 후보도 함께 좁혀집니다.

## 확인 필요 체크 및 초기화

### 공통 원칙

- 대상 범위: 항상 `현재 필터 결과`
- 저장 대상:
  - `shape_index >= 0`인 실제 라벨 행만 저장
  - `base_state`가 오류인 행만 `확인 필요 체크` 대상
- 저장 형식:
  - `is_problem`
  - `problem_reason`
- 사유 입력 시 저장 형식:
  - `[YYYY-MM-DD HH:MM:SS] 사유`
  - 여러 사유는 줄바꿈으로 누적

### 확인 필요 체크

- 현재 필터 결과 중 오류 행만 골라 `is_problem=True`와 사유를 S3 JSON에 반영합니다.
- 완료 로그 예시:
  - `확인 필요 체크 완료: 범위=현재 필터 결과 / 수정 페이지 N건 / 대상 행 M건`

### 확인 필요 초기화

초기화는 세 가지 경로가 있습니다.

- `현재 필터 결과 초기화`
  - 현재 필터 결과 중 `is_problem=True`인 항목만 초기화
- `검수 도서 전체 초기화`
  - 현재 로딩된 전체 라벨 행에서 `is_problem=True`인 항목을 초기화
- `특정 problem_reason 항목 초기화`
  - 현재 필터 결과에 있는 timestamped reason line 중 하나를 골라 해당 사유만 제거

### S3 최신본과 스냅샷 비교 방식

`확인 필요 체크`, `현재 필터 결과 초기화`, `특정 reason 초기화`는 스냅샷과 최신 S3 JSON이 같은지 먼저 확인합니다.

- 비교 시 제외하는 필드:
  - `is_problem`
  - `problem_reason`
- 비교 목적:
  - 검수 중 다른 수정이 들어간 페이지에 잘못 덮어쓰지 않기 위해서

이 세 흐름에서 스냅샷 불일치가 있으면 작업을 중단합니다.

- 경고 메시지 성격:
  - `스냅샷과 다른 JSON이 N건 감지되어 작업을 진행하지 않습니다.`

반면 `검수 도서 전체 초기화`는 최신본을 기준으로 전체 정리하는 성격이라, 스냅샷 일치 여부를 강제하지 않고 진행합니다.

### 저장 제외/중단 사유

운영 중 자주 보게 되는 저장 제외 사유는 아래와 같습니다.

- `최신 S3 JSON 로드 실패`
- `JSON 정보 없음`
- `최신 JSON 정보 이상`
- `스냅샷 JSON 없음`
- `JSON shapes 구조 이상`
- `스냅샷 불일치`
- `확인 필요 저장 실패`

README를 수정할 때는 이 사유와 실제 로그/경고 문구가 어긋나지 않는지 같이 보는 편이 좋습니다.

## 미리보기 영역

오른쪽 미리보기 영역은 현재 선택한 행의 페이지를 기준으로 동작합니다.

- 이미지
  - 현재 페이지의 이미지 파일을 캐시 경로에서 불러옵니다.
- 박스
  - 기본적으로 스냅샷 JSON의 shape 전체를 읽어 bbox 목록을 만듭니다.
  - 라벨 색상은 `label/` 기준표를 우선 사용합니다.
- 강조 방식
  - 선택한 행의 `shape_index`가 있으면 해당 박스만 강조하고 나머지는 tone-down 처리
  - shape를 바로 찾을 수 없으면 `label_id` 기준으로 다시 시도
- fallback
  - 스냅샷에서 shape를 만들 수 없으면 `last_page_issues` 기반 bbox를 fallback으로 사용

즉, 미리보기는 “현재 페이지 전체 박스를 보여주되, 선택한 오류 위치만 더 눈에 띄게” 만드는 방식입니다.

## 통계 영역

오른쪽 `통계` 탭과 상단 요약은 서로 연결되어 있습니다.

### 상단 요약

- `도서 수`
- `페이지 수`
- `오류 페이지`
- `총 오류`
- `통과율`

이 값은 현재 로딩된 검사 결과를 기준으로 갱신됩니다.

### 오른쪽 통계 탭

- `개요`
  - 선택된 도서 범위 기준 KPI 요약
- `유형별 오류 통계`
  - 오류 유형별 개수
  - 오류 페이지 수
  - 비중
- `도서별 오류 통계`
  - 도서별 오류율 분포 차트
  - 도서별 오류 수 / 오류 페이지 수 표

오른쪽 통계는 왼쪽에서 선택된 도서 범위와 현재 집계된 `current_issues`, `label_rows`를 기준으로 다시 계산됩니다.

## 유지보수 포인트

- 새로운 규칙은 가능하면 `plugins/` 아래 플러그인으로 추가합니다.
- 조회/실행 속도 이슈를 볼 때는 단순 UI보다 `json_snapshot_worker.py`, `check_run_worker.py`, `resolve_parallel_workers()` 쪽을 먼저 봅니다.
- 중앙 패널 필터 구조를 바꾸면 `확인 필요` 저장 범위도 함께 달라지므로 `problem_sync_strict.py`까지 같이 확인해야 합니다.
- 스냅샷 비교 정책을 바꿀 때는 `확인 필요` 체크/초기화, 미리보기, 실행 기준이 모두 영향을 받습니다.
- 결과 행 필드명을 바꾸면 중앙 패널, 미리보기, 통계, `확인 필요` 저장 로직이 함께 영향을 받습니다.
